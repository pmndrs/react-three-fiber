## Prop Utilities

v10 adds two utilities for common prop patterns that previously required imperative code.

### `fromRef` — deferred ref resolution

`fromRef` defers prop application until a ref is populated. This is essential for props like `target` that reference sibling elements, replacing the old mount-time `useEffect`:

```tsx
import { fromRef } from '@react-three/fiber'

function SpotlightWithTarget() {
  const targetRef = useRef<THREE.Object3D>(null)
  return (
    <>
      <group ref={targetRef} position={[0, 0, -10]} />
      {/* target resolves after targetRef is populated */}
      <spotLight target={fromRef(targetRef)} intensity={100} />
    </>
  )
}
```

When the prop needs the sibling _wrapped_ rather than assigned as-is, pass a transform as the second argument. It runs once the ref is populated and its result is what gets assigned:

```tsx
import { lights } from 'three/tsl'

// A node material's lightsNode needs a LightsNode, not the light itself
<meshPhongNodeMaterial lightsNode={fromRef(lightRef, (light) => lights([light]))} />
```

Only top-level props on a three element are resolved. A marker nested inside another value (an array, an options object) or passed to a React component is not seen.

### `once` — mount-only method calls

`once` marks a method prop to be applied only on initial mount, which is useful for geometry transforms that shouldn't compound every render:

```tsx
import { once } from '@react-three/fiber'

// Rotate geometry 90° on mount (without `once` this compounds every render)
<boxGeometry args={[1, 1, 1]} rotateX={once(Math.PI / 2)} />

// Center geometry on mount
<bufferGeometry center={once()} />

// Apply a matrix on mount
<bufferGeometry applyMatrix4={once(transformMatrix)} />

// Multi-argument methods take the arguments directly
<planeGeometry args={[10, 10]} translate={once(0, 0, 5)} />
```

`once` is typed as the value the prop declares: a single argument is the argument itself, several arguments are the tuple, and a bare `once()` is `true`. Pass the arguments individually, not as an array: `once([0, 0, 5])` calls `translate([0, 0, 5])`.

When `args` change (triggering element reconstruction), `once` methods run again on the new instance.

## Extending the root {#extending-the-root}

These are for packages that build on R3F, such as `@react-three/tsl`. App code rarely needs them.

### `registerRootExtension`

Registers per-root setup, cleanup and hot-reload handling without R3F knowing about your package.

```tsx
import { registerRootExtension } from '@react-three/fiber/extension'

registerRootExtension({
  name: 'my-library',
  // Once per root, after its renderer exists and before onCreated and the first frame.
  // Return fields to merge into the root's state, or nothing to skip this root.
  setup(store) {
    if (store.getState().isLegacy) return
    return { /* per-root state */ }
  },
  // When a root this extension set up unmounts.
  dispose(store) {},
  // When <Canvas> detects hot module replacement (skipped with hmr={false}).
  hmr(store) {},
})
```

- Roots that already exist when you register are set up immediately; later roots as they are created.
- Registering the same `name` again replaces the entry, which keeps hot reloads safe: roots it already set up are not set up twice, and the new entry's `dispose` and `hmr` take over.
- The function returned by `registerRootExtension` unregisters it. Roots it already set up keep their state and still get `dispose` when they unmount.

### `setRenderOverride`

Points a root's default render job at your own render function, for example a post-processing pipeline. Pass `null` to go back to `renderer.render(scene, camera)`.

```tsx
import { setRenderOverride, useStore } from '@react-three/fiber/extension'

const store = useStore()
setRenderOverride(store, () => composer.render())
```

Unlike taking over the `render` phase with `useFrame`, the default job keeps its behaviour: the Canvas `fps` throttle, error reporting to the error boundary, and backing off when a user registers a `{ phase: 'render' }` job. `useRenderPipeline` renders through this.

### The `@react-three/fiber/extension` entry

Every entry shares one core, and nothing in that core imports three: a library can import hooks from `@react-three/fiber` and add no renderer and no second copy of fiber to an app on any entry.

`@react-three/fiber/extension` is the smallest stable surface for a package that builds on fiber: `useStore`, `useThree`, `useFrame`, `context`, `registerRootExtension`, `setRenderOverride` and the shared types, and nothing that could ever grow a renderer. It works under a `<Canvas>` from any entry. Apps should keep importing from `@react-three/fiber`, `/webgpu` or `/legacy`.

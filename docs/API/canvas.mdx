The `Canvas` object is where you start to define your React Three Fiber Scene.

```jsx
import React from 'react'
import { Canvas } from '@react-three/fiber'

const App = () => (
  <Canvas>
    <pointLight position={[10, 10, 10]} />
    <mesh>
      <sphereGeometry />
      <meshStandardMaterial color="hotpink" />
    </mesh>
  </Canvas>
)
```

## Properties

| Prop            | Description                                                                                                                                       | Default                                                    |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| children        | three.js JSX elements or regular components                                                                                                       |                                                            |
| fallback        | optional DOM JSX elements or regular components in case GL is not supported                                                                       |                                                            |
| renderer        | Selects/configures the renderer. Omit for WebGL (default). Pass `renderer` (boolean shorthand for `renderer={{}}`), a props bag, a renderer instance, or a sync/async callback to use **WebGPU** — R3F handles `init()` for you. The props bag takes constructor parameters, renderer properties and R3F's renderer settings `shadows` and `textureColorSpace`; all of it is honored only by a canvas that owns its renderer (see [Renderer settings](#renderer-settings)) | WebGL |
| gl              | **Deprecated** — WebGL-only renderer props/instance. Prefer `renderer`. Accepts sync/async callback with default props `gl={defaults => new Renderer({ ...defaults })}`, and the same `shadows` / `textureColorSpace` settings as `renderer` | `{}`                                  |
| id              | Canvas id: sets the `<canvas>` element's `id`, names the canvas for `scheduler` `before`/`after`, and for `share="id"` on a `primary` | `undefined` |
| primary         | **WebGPU.** This canvas owns the renderer other canvases share: every other WebGPU canvas mounted with or after it borrows its renderer unless it passes `share={false}` or its own renderer instance/factory. | scheduler       | This canvas's place in the frame loop: `{ before, after, order, fps }`. `before`/`after` take canvas ids, `order` sorts numerically (lower first), `fps` caps the default render. A canvas sharing a primary's renderer renders after it unless `before`/`after` is set. See [Frame Loop](../frame-loop#ordering-canvas-roots) | `undefined` |
| camera          | Props that go into the default camera, or your own `THREE.Camera`                                                                                 | `{ fov: 75, near: 0.1, far: 1000, position: [0, 0, 5] }`   |
| scene           | Props that go into the default scene, or your own `THREE.Scene`                                                                                   | `{}`                                                       |
| background      | Sets the scene background — a CSS color, hex number, `THREE.Color`, a Drei environment preset name, an HDR/EXR/image URL, or a config object. See [Canvas Background](#canvas-background) | `undefined`                            |
| raycaster       | Props that go into the default raycaster                                                                                                          | `{}`                                                       |
| frameloop       | Render mode: always, demand, never                                                                                                                | `always`                                                   |
| resize          | Resize config, see react-use-measure's options                                                                                                    | `{ scroll: true, debounce: { scroll: 50, resize: 0 } }`    |
| orthographic    | Creates an orthographic camera                                                                                                                    | `false`                                                    |
| dpr             | Pixel-ratio, use `window.devicePixelRatio`, or automatic: [min, max]                                                                              | `[1, 2]`                                                   |
| width           | Fixed drawing-buffer width in pixels. When set, R3F stops auto-sizing to the container width. See [Canvas Size Control](#canvas-size-control)     | container width                                            |
| height          | Fixed drawing-buffer height in pixels. When set, R3F stops auto-sizing to the container height                                                    | container height                                           |
| forceEven       | Round computed width/height down to even numbers (useful for video encoders)                                                                      | `false`                                                    |
| events          | Configuration for the event manager, as a function of state                                                                                       | `import { events } from "@react-three/fiber"`              |

| autoUpdateFrustum | Enable/disable automatic camera frustum updates each frame                                                                                      | `true`                                                     |

## Defaults

Canvas uses [createRoot](#createroot) which will create a translucent `THREE.WebGLRenderer` with the following constructor args:

- antialias=true
- alpha=true
- powerPreference="high-performance"

and with the following properties:

- outputColorSpace = THREE.SRGBColorSpace
- toneMapping = THREE.ACESFilmicToneMapping

It will also create the following scene internals:

- A `THREE.Perspective` camera
- A `THREE.Orthographic` cam if `orthographic` is true
- A `THREE.PCFShadowMap` if `renderer={{ shadows: true }}` (or `gl={{ shadows: true }}`)
- A `THREE.Scene` (into which all the JSX is rendered) and a `THREE.Raycaster`

In recent versions of threejs, `THREE.ColorManagement.enabled` will be set to `true` to enable automatic conversion of colors according to the renderer's configured color space. R3F will handle texture color space conversion. For more on this topic, see [https://threejs.org/manual/#en/color-management](https://threejs.org/manual/#en/color-management).

## Errors and fallbacks

On some systems WebGL may not be supported, you can provide a fallback component that will be rendered instead of the canvas:

```jsx
<Canvas fallback={<div>Sorry no WebGL supported!</div>}>
  <mesh />
</Canvas>
```

You should also safeguard the canvas against WebGL context crashes, for instance if users have the GPU disabled or GPU drivers are faulty.

```jsx
import { useErrorBoundary } from 'use-error-boundary'

function App() {
  const { ErrorBoundary, didCatch, error } = useErrorBoundary()
  return didCatch ? (
    <div>{error.message}</div>
  ) : (
    <ErrorBoundary>
      <Canvas>
        <mesh />
      </Canvas>
    </ErrorBoundary>
  )
}
```

> [!NOTE]
> Ideally, and if possible, your fallback is a seamless, visual replacement for what the canvas would have otherwise rendered.

## Canvas Background

The `background` prop sets the scene background (and, for environment maps, image-based lighting) declaratively — replacing manual `<color attach="background">` or a separate Environment component for simple cases.

```tsx
// Color (CSS color names, hex strings, rgb(), or a hex number)
<Canvas background="red" />
<Canvas background="#1a1a2e" />
<Canvas background={0xff0000} />

// Drei environment preset (apartment, city, dawn, forest, lobby, night, park, studio, sunset, warehouse)
<Canvas background="sunset" />

// URL to an HDR/EXR/image file
<Canvas background="/env.hdr" />
<Canvas background="./sky.jpg" />

// Six cube faces (+x, -x, +y, -y, +z, -z); `.hdr` faces load as an HDR cubemap
<Canvas background={{ files: ['px.hdr', 'nx.hdr', 'py.hdr', 'ny.hdr', 'pz.hdr', 'nz.hdr'], path: '/pisa/' }} />
```

When a **string** is given it is resolved in this order: exact **preset** name → **URL** (starts with `/`, `./`, `../`, `http://`, `https://`, or ends in `.hdr`/`.exr`/`.jpg`/`.jpeg`/`.png`/`.webp`/`.gif`) → otherwise a **CSS color**. So `"city"` is a preset, `"./city.jpg"` is a URL, and `"cyan"` is a color.

For separate backdrop and environment maps, pass an object:

```tsx
<Canvas
  background={{
    preset: 'city', // or files: '/env.hdr'
    backgroundMap: '/sky.jpg', // optional separate visual backdrop
    backgroundBlurriness: 0.5,
    backgroundIntensity: 1,
    environmentIntensity: 1.2,
    path: '/textures/',
  }}
/>
```

The underlying `Environment` component is also exported from `@react-three/fiber` for direct use.

## Canvas Size Control

By default the canvas auto-sizes to its container. The `width`/`height` props pin the drawing-buffer resolution instead — independent of CSS size — which is useful for fixed-resolution capture such as video export.

```tsx
// Fixed resolution regardless of container size
<Canvas width={1920} height={1080}>
  <Scene />
</Canvas>

// Partial: width pinned, height from container
<Canvas width={800}>
  <Scene />
</Canvas>

// 4K capture (set dpr={1} for exact pixel dimensions)
<Canvas width={3840} height={2160} dpr={1}>
  <Scene />
</Canvas>
```

Size follows an ownership model: props (or container fallback) drive size until you call `setSize()` imperatively, which takes ownership; call `setSize()` with no arguments to release back to props/container.

```tsx
const { setSize } = useThree()
setSize(3840, 2160) // imperative mode, 4K
setSize(1024) // 1024×1024 square
setSize() // reset to props/container
```

> [!NOTE]
> `width`/`height` are logical pixels; DPR multiplies as usual. Set `dpr={1}` for exact pixel dimensions. Use `forceEven` to round dimensions down to even numbers for video encoders.

## Renderer settings

Renderer-wide settings go into the `renderer` prop (WebGPU) or `gl` prop (WebGL): constructor parameters (`antialias`, `forceWebGL`, `depth`, ...), renderer properties (`toneMapping`, `outputColorSpace`, ...), and two settings R3F applies itself:

- `shadows`: `true` for `THREE.PCFShadowMap`, one of `'basic'`, `'percentage'`, `'soft'`, `'variance'`, or props assigned to `renderer.shadowMap`. `'soft'` is kept only as a deprecated alias of `'percentage'`: both use `THREE.PCFShadowMap` (three.js deprecated `PCFSoftShadowMap` and made `PCFShadowMap` soft), and `'soft'` logs a deprecation notice. Default `false`. Applied to a renderer R3F builds; a renderer instance or factory keeps the `shadowMap` you give it.
- `textureColorSpace`: the color space of 8-bit input textures loaded in this canvas.

```tsx
<Canvas renderer={{ shadows: 'variance', toneMapping: THREE.AgXToneMapping }} />
```

These configure a renderer the canvas owns. A canvas sharing a `<Canvas primary>`'s renderer ignores them (with a development warning) because the primary owns the renderer; `textureColorSpace`, which is per canvas, still applies. Constructor parameters are read once, when the renderer is built: changing them later has no effect.

### Color settings

Renderer color options — `textureColorSpace`, `outputColorSpace`, `toneMapping`:

```tsx
// WebGL
<Canvas gl={{ outputColorSpace: THREE.LinearSRGBColorSpace, toneMapping: THREE.NoToneMapping, textureColorSpace: THREE.LinearSRGBColorSpace }} />

// WebGPU
<Canvas renderer={{ outputColorSpace: THREE.LinearSRGBColorSpace, toneMapping: THREE.NoToneMapping, textureColorSpace: THREE.LinearSRGBColorSpace }} />
```

Defaults: `outputColorSpace` = `THREE.SRGBColorSpace`, `toneMapping` = `THREE.ACESFilmicToneMapping`, `textureColorSpace` = `THREE.SRGBColorSpace`.

## WebGPU

Recent Three.js ships a WebGPU renderer that requires async initialization. In v10 you opt in with the `renderer` prop and R3F handles `init()` for you — no manual `await renderer.init()`:

```tsx
import { Canvas } from '@react-three/fiber'

export default () => (
  <Canvas renderer>
    <mesh>
      <meshBasicNodeMaterial />
      <boxGeometry />
    </mesh>
  </Canvas>
)
```

`renderer` (the boolean shorthand for `renderer={{}}`) also accepts a config bag, a renderer instance, or a sync/async callback. R3F disposes a renderer it built from a config bag or a callback once the last Canvas using it unmounts; an instance you pass in is yours to dispose. Only the renderer a Canvas asks for is downloaded: three's WebGPU renderer is a separate chunk fetched when a `<Canvas renderer>` mounts, and a plain `<Canvas>` fetches only the WebGL one. For the single-renderer entries, node materials as JSX, TSL hooks, and multi-canvas, see the [WebGPU section](../webgpu/overview).

Node materials and TSL need `WebGPURenderer`, so pass `renderer` to use them. Browser WebGPU support is not required: `WebGPURenderer` falls back to WebGL2 automatically.

## Custom Canvas

R3F can render to a root, similar to how `react-dom` and all the other React renderers work. This allows you to shave off `react-dom` (~40kb), `react-use-measure` (~3kb) and, if you don't need them, `pointer-events` (~7kb) (you need to explicitly import `events` and add them to the config otherwise).

Roots have the same options and properties as `Canvas`, but you are responsible for resizing it. It requires an existing DOM `<canvas>` object into which it renders.

### CreateRoot

Creates a root targeting a canvas, rendering JSX.

```jsx
import { createRoot, events } from '@react-three/fiber'

// Create a react root. Three's classes are JSX elements on it without any extend() call:
// the root resolves element names against the namespace of the renderer it loads.
const root = createRoot(document.querySelector('canvas'))

// Keep the whole configuration in one object: each configure() call replaces the previous one
const config = { events, camera: { position: [0, 0, 50] } }

async function app() {
  // Configure the root, inject events optionally, set camera, etc
  // This *must* be called before render, and it must be awaited
  await root.configure(config)

  // createRoot by design is not responsive, you have to take care of resize yourself.
  // Pass the same config again with the new size, not just the size on its own
  window.addEventListener('resize', () => {
    root.configure({ ...config, size: { width: window.innerWidth, height: window.innerHeight } })
  })

  // Trigger resize
  window.dispatchEvent(new Event('resize'))

  // Render entry point
  root.render(<App />)

  // Unmount and dispose of memory
  // root.unmount()
}

app()
```

`configure()` replaces the root's configuration rather than merging into it, the same way `<Canvas>` passes its full set of props every time it renders. A prop left out of a later call goes back to its default: calling `root.configure({ size })` on its own drops the `renderer` or `gl` settings (turning shadows off) and resets `frameloop` to `'always'` and `dpr` to `[1, 2]`. So keep one config object and spread it into every call, changing only what's new.

The camera, the scene and the `events` manager are the exception: the camera and scene are created by the first call, the `events` manager by the first call that passes `events`, and all three are kept after that. Leaving `camera` out of a later call does not reset the camera, and `camera` props passed to a later call are not re-applied. To move the camera after the first `configure()`, change it from inside the tree (`useThree`) or through the store `root.render()` returns.

## Tree-shaking

What a bundle carries is decided by the renderer, not by which elements you use. Fiber's core imports nothing from three; a root loads one renderer's support module (`three` for WebGL, `three/webgpu` for WebGPU) when it mounts, and that module carries the whole namespace of its flavour. So an app on `@react-three/fiber` ships no three code eagerly, downloads only the renderer its Canvas asks for, and never both. Three's own classes are not tree-shaken below that: `<mesh>` and `<boxGeometry>` resolve against the loaded namespace, and an `extend({ Mesh, BoxGeometry })` call does not remove anything from it.

`extend` is for classes three does not ship, such as addons and your own subclasses:

```jsx
import { extend, createRoot } from '@react-three/fiber'
import { OrbitControls } from 'three/examples/jsm/controls/OrbitControls.js'

extend({ OrbitControls })

createRoot(canvas).render(
  <>
    <orbitControls args={[camera, domElement]} />
    <mesh>
      <boxGeometry />
      <meshStandardMaterial />
    </mesh>
  </>,
)
```

The `/legacy` and `/webgpu` entries import their renderer statically instead, for apps that would rather skip the extra request. See [Entry Points](../webgpu/overview#entry-points) for the comparison.
